The Core Challenge — Class Imbalance

Out of every 100 machine operating cycles, only ~3 fail. A model that always predicts "healthy" would score 96.61% accuracy yet catch 0% of real breakdowns. We need Precision, Recall & F1 — not raw accuracy.

1
Leak-Free Pipeline

Remove 5 diagnostic fault flags that directly define the target — if kept, accuracy is artificially 100%.

2
Physics-Driven Features

Translate raw sensor readings into meaningful engineering quantities: heat margin, mechanical power, cumulative strain.

3
Fair Model Comparison

Benchmark a linear baseline against two tree ensembles using 5-fold stratified cross-validation.

4
High Practical Performance

Reach F1 ≥ 0.80 and PR-AUC ≥ 0.85 on an untouched 15% holdout while keeping false alarms near zero.

Data Preprocessing & Feature Engineering

Remove leakage, engineer physics-based features, audit statistics

Not Run
Target Leakage — Critical Step

The 5 failure sub-flags (TWF, HDF, PWF, OSF, RNF) are post-breakdown diagnostic codes. Their logical OR equals the target exactly — keeping them gives fake 100% accuracy but is completely useless in production. We remove all 5.

Temp_Diff_K
Process Temp − Air Temp
Heat dissipation margin. A small gap means cooling is insufficient → overheating.
Power_W
Torque × (RPM × 2π / 60)
True mechanical power (Watts). Captures both low-speed stalling and high-speed overload.
Overstrain_Index
Tool wear × Torque
Cumulative strain product. A dull tool under high force is primed to snap or jam.

Stratified Train / Val / Test Split

70% Train · 15% Validation · 15% Untouched Test (all stratified)

Not Run
Why Stratified Splitting?

With only 3.39% failures, a random split could accidentally place all failures in one partition. Stratified splitting ensures each of Train, Validation, and Test maintains the same 3.39% failure rate. The Test set is locked away until the very end — zero leakage.

Click Run to create the stratified splits. Requires: Preprocessing

Why Precision-Recall, Not ROC?

With 96.6% healthy samples, ROC-AUC is dominated by the abundant negative class and looks artificially optimistic. PR-AUC focuses solely on the minority failure class — it directly answers: "Of all our alerts, how many are real? And of all real failures, how many did we catch?"

Error Analysis

Not Run
Why Inspect Errors?

A model's mistakes reveal its limits. False Negatives (missed failures) are operationally costly — the machine breaks down. False Positives (unnecessary alerts) waste maintenance labour. By examining the sub-failure types (TWF, HDF, etc.) inside missed cases, we understand which failure physics the model hasn't mastered.
